# ChatterBat

A native macOS chat client for your own Venice and OpenRouter API accounts.

ChatterBat is not a hosted service. You bring your own API keys, and you pay
Venice and/or OpenRouter directly. This app is a local, Keychain-backed,
SwiftUI front end for chatting with the models available on either service,
with an emphasis on fast, honest model switching.

## Current status

Stage 0 (buildable native foundation) is complete. There is no provider
networking, no account connection, and no chat functionality yet — see
`docs/STATUS.md` for exactly what exists and what's next.

## Requirements

- macOS 14 or later to run the app.
- Xcode 26 (or a compatible toolchain with Swift 6 language mode support) to
  build it.
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) to (re)generate
  `ChatterBat.xcodeproj` from `project.yml`. Install with:

  ```
  brew install xcodegen
  ```

## Project structure

```
ChatterBat/
  App/            App entry point (ChatterBatApp.swift)
  Domain/         Plain value types (Conversation, demo fixtures)
  Features/       SwiftUI views + view models, grouped by feature
  Persistence/     (empty until Stage 4 — SwiftData repository)
  Services/        (empty until Stage 1 — Keychain, provider adapters)
  Design/          (empty until shared design tokens are needed)
  Resources/       Entitlements, asset catalog
ChatterBatTests/    XCTest unit tests
ChatterBatUITests/  XCUITest UI tests
docs/               Development plan, status, and decisions
project.yml         XcodeGen project specification (source of truth)
ChatterBat.xcodeproj  Generated by XcodeGen — do not hand-edit
```

The `.xcodeproj` is generated, not hand-authored. If you edit `project.yml`,
regenerate the project before opening Xcode:

```
xcodegen generate
```

## Build and run

Open in Xcode:

```
open ChatterBat.xcodeproj
```

Then select the **ChatterBat** scheme and Run (⌘R).

Or from the command line:

```
xcodebuild \
  -project ChatterBat.xcodeproj \
  -scheme ChatterBat \
  -configuration Debug \
  -destination 'platform=macOS' \
  -derivedDataPath /tmp/ChatterBatDerivedData \
  build
```

## Run tests

```
xcodebuild \
  -project ChatterBat.xcodeproj \
  -scheme ChatterBat \
  -destination 'platform=macOS' \
  -derivedDataPath /tmp/ChatterBatDerivedData \
  test
```

**Known limitation:** in this development environment, the XCUITest target
(`ChatterBatUITests`) fails to load with a code-signing "different Team IDs"
error when run via `xcodebuild test` end to end, because Xcode's automatic
signing requires an Xcode-managed developer account/provisioning profile
that isn't configured non-interactively here. The app target itself builds,
signs (ad hoc), and launches correctly, and all `ChatterBatTests` unit tests
pass. To run UI tests, either sign in to an Apple Developer account in
Xcode's Settings → Accounts and let Xcode manage signing, or run the UI test
target directly from within Xcode on a machine with an interactive session
and a properly provisioned signing identity. Run just the unit tests with:

```
xcodebuild \
  -project ChatterBat.xcodeproj \
  -scheme ChatterBat \
  -destination 'platform=macOS' \
  -derivedDataPath /tmp/ChatterBatDerivedData \
  -only-testing:ChatterBatTests \
  test
```

## Security and privacy posture

- API keys are stored in the macOS Keychain only (Stage 1 onward). They are
  never written to UserDefaults, SwiftData, logs, or source files.
- No telemetry. No hidden network calls. Requests go directly from this app
  to the service you selected (Venice or OpenRouter) — never through a
  ChatterBat-operated server, because there isn't one.
- Local conversation history relies on standard macOS app-sandbox storage
  protections; it is not separately encrypted unless a future stage says so
  explicitly.
